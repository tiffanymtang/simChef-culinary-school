Why simulations?

Simulations are a powerful and ubiquitous tool in the modern scientific process.

They can be used to quickly

  • screen hypotheses and identify those worth pursuing
  • model natural systems under specific or rare conditions
  • stress-test emerging theories and methods

Importantly, simulations offer full control over experimental conditions.

What makes a “high-quality” simulation?

Building upon PCS, a “high-quality” simulation should be one with MERITS

M
Modular: written in self-contained and logically partitioned segments of code
E
Efficient: streamlined computationally and conceptually
R
Realistic: faithful to the natural world or realm of application, to the best extent allowed by established theory and/or available real-world data
I
Intuitive: sensible to the intended audience and a broad range of potential consumers, across all parts of the pipeline: simulation architecture, documentation, code, and analysis of results
T
Transparent: documented thoroughly and candidly
S
Stable: reproducible, replicable, and (potentially) generalizable beyond the scope of the simulation

Overview of simChef

simChef is a versatile R package to create high-quality simulations with MERITS, with PCS as the guiding framework.

The simChef Vision

  • Allow data scientists to focus on substantive questions with fewer technical distractions
  • Lower the activation barrier to running high-quality simulation studies
  • Provide comprehensive simulation documentation and archive of simulation artifacts for transparency and reproducibility

simChef Highlights

  • A tidy grammar for simulation studies

Case Study: Interaction Discovery with iRF

Iterative Random Forests (iRF): computationally efficient tree-based method for detecting stable, high-order interactions in high-dimensional data (Basu et al. 2018)

Applications:

  • Transcription factor interactions in Drosophila embryos[1]
  • Chromatin interactions associated with alternative splicing[1]
  • Genetic interactions (epistasis) associated with red hair, multiple sclerosis,[2] and cardiac hypertrophy[3]
  • Chemical exposure interactions associated with child neurodevelopment[4]
[1] Basu et al. (2018). “Iterative random forests to discover predictive and stable high-order interactions.” PNAS.
[2] Behr et al. (2024). “Learning epistatic polygenic phenotypes with Boolean interactions.” PLOS ONE.
[3] Wang et al. (2025). “Epistasis regulates genetic control of cardiac hypertrophy.” Nature Cardiovascular Research.
[4] Midya et al. (2023). “Machine learning assisted discovery of interactions between pesticides, phthalates, phenols, and trace elements in child neurodevelopment.” Environmental Science & Technology.

See case-studies/interaction_discovery.R for reproducible simulation script

How to construct a realistic and meaningful DGP?
\(y = f(X) + \varepsilon\)
Choice of \(X\)
  • Use (bootstrapped or subsampled) real data for \(X\) to preserve realistic feature distributions and correlation structures
Choice of \(f\)
  • Use domain knowledge or existing models to inform choice of \(f\)
  • Fit model using real data to estimate parameters and then simulate using these estimated parameters
Choice of \(\varepsilon\)
  • Fit model using real data and bootstrap the residuals to create realistic noise
E.g., Drosophila enhancer data
E.g., Boolean interactions (LSS model) to mimic on/off thresholding behavior of genes
E.g., RF noise

Case Study: Creating the DGP

DGPMethodEvaluatorVisualizer
1 Define generate_xy_data() 
generate_xy_data <- function(X, rf_probs, n) {
  fx <- (X[, "kr1"] > 1.25 | X[, "kr2"] > 1.25) &
    (X[, "twi1"] > 1.25 | X[, "twi2"] > 1.25) &
    (X[, "D1"] > 1.25) &
    (X[, "hb1"] > 1.25 | X[, "hb2"] > 1.25) &
    (X[, "wt_ZLD"] > 75)

  y <- as.integer(fx | (runif(nrow(X)) < rf_probs))
  split <- stratified_split(y, train_prop = n / nrow(X))

  list(
    X_train = X[split$train, , drop = FALSE],
    y_train = factor(y[split$train], levels = c(0, 1)),
    X_test = X[split$test, , drop = FALSE],
    y_test = factor(y[split$test], levels = c(0, 1)),
    true_interaction = c("D1", "hb", "kr", "twi", "wt.ZLD")
  )
}
2 Create the DGP 
dgp <- simChef::create_dgp(
  .dgp_fun = generate_xy_data,
  .name = "Enhancer LSS with RF Noise",
  # named arguments to pass to generate_xy_data
  X = X,
  rf_probs = rf_probs,
  n = 400
)
In this recipe: n can be varied with add_vary_across(); the named train/test objects and true interaction are passed to fit_irf().

Case Study: Creating the Method

DGPMethodEvaluatorVisualizer
1 Define fit_irf() 
fit_irf <- function(X_train, y_train, X_test, y_test,
                    true_interaction, niter, ...) {
  fit <- iRF::iRF(
    x = X_train, y = y_train,
    xtest = X_test, ytest = y_test,
    iter.return = niter, int.return = niter,
    signed = FALSE, verbose = FALSE, n.core = 1,
    ...
  )

  list(
    rf_fit = fit$rf.list,
    interactions = fit$interaction,
    y_test = y_test,
    true_interaction = true_interaction
  )
}
2 Create the Method 
irf <- simChef::create_method(
  .method_fun = fit_irf,
  .name = "iRF",
  # named arguments to pass to fit_irf
  varnames.grp = var_groups,
  niter = 5,
  n.bootstrap = 20,
  rit.param = list(
    depth = 5, ntree = 100, nchild = 2,
    class.id = 1, min.nd = 1
  )
)
In this recipe: arguments from the DGP match the inputs to fit_irf(); its named outputs contain everything needed by the evaluators.

Case Study: Creating an Evaluator

DGPMethodEvaluatorVisualizer
1 Define the evaluator functions 
eval_summary <- function(fit_results, vary_params = NULL,
                         eval_id, eval_fun) {
  group_ids <- c(".dgp_name", ".method_name", vary_params,
                 "interaction_order", "active")

  fit_results |>
    dplyr::rowwise() |>
    dplyr::mutate("{eval_id}" := eval_fun(
      rf_fit = rf_fit, interactions = interactions,
      y_test = y_test,
      true_interaction = true_interaction
    )) |>
    tidyr::unnest(cols = dplyr::all_of(eval_id)) |>
    dplyr::group_by(dplyr::across(dplyr::any_of(group_ids))) |>
    dplyr::summarise(dplyr::across(
      dplyr::all_of(eval_id),
      list(mean = mean, raw = list),
      .names = "{.fn}_{.col}"
    ), .groups = "drop")
}
eval_prediction <- function(rf_fit, y_test, ...) {
  yardstick::pr_auc_vec(
    y_test, rf_fit$test$votes[, "1"],
    event_level = "second"
  )
}
2 Create the Evaluator 
prediction <- simChef::create_evaluator(
  .eval_fun = eval_summary,
  .name = "AUPRC",
  # named arguments to pass to eval_summary
  eval_id = "auprc",
  eval_fun = eval_prediction
)
Same pattern: replace the metric and name to create the interaction_recovery and stability evaluators.
